# 批量导入提示词设计

## 状态

- 日期：2026-08-18
- 状态：已确认，等待用户复核书面设计后进入实施计划
- 功能名称：批量导入提示词

## 背景

当前任务编辑器提供“批量粘贴”，按换行将文本拆成“一行一个提示词”。实际 PPT 生图提示词由多个段落组成，并使用固定标记区分页面信息、提示词正文、画面文字和关键元素。按换行拆分会把同一页错误地变成多条任务。

用户会把整份结构化提示词直接粘贴进应用，不上传 Word 文件。Word 文档只用于说明文本格式。

结构化文本中的每页包含以下五个字段：

```text
【页面编号】P1
【页面名称】AI数学乐园系统故障
【生图提示词】
多段正文……
【画面核心文字】
多行文字……
【关键画面元素】
元素一；元素二；元素三
```

## 目标

1. 将整份结构化提示词文本一次解析为多条任务。
2. 每页生成一条任务，导入数量与任务行数量完全一致。
3. 将页面编号和页面名称作为只读备注展示并持久化。
4. 备注不进入生图提示词，也不发送给远程生图服务。
5. 保留现有“一行一个提示词”的简单导入能力。
6. 在覆盖现有任务前明确确认，解析失败时不改变现有任务。

## 非目标

- 不上传或解析 `.docx` 文件。
- 不自动提交生图任务。
- 不根据页面编号重新排序。
- 不为备注增加手动编辑功能。
- 不在历史列表、当前批次卡片或导出文件名中新增备注展示。
- 不调整模型、比例、分辨率、张数或参考图的现有默认逻辑。

## 方案选择

采用“前端结构化解析 + 导入预览 + 后端持久化备注”。

未采用的方案：

- 后端解析接口：会增加不必要的网络往返和接口复杂度，无法改善当前纯文本解析问题。
- 无预览的自动拆分：实现更少，但格式异常时容易静默导错，不适合几十页提示词。

## 用户交互

### 入口

将任务编辑器工具栏中的“批量粘贴”更名为“批量导入提示词”。弹窗继续提供一个大文本框，不提供文件上传控件。

### 自动识别

- 文本中只要出现结构化字段标记，就进入结构化解析模式。
- 结构化模式解析失败时不回退到逐行模式，避免错误拆分。
- 未出现结构化标记时，按原有“一行一个提示词”模式处理。

### 预览

弹窗在导入前显示：

- 当前识别模式。
- 识别出的任务数量。
- 结构化模式下每条任务的备注，例如 `P1 · AI数学乐园系统故障`。
- 所有阻止导入的错误及对应页面。

### 覆盖规则

- 导入会替换当前任务列表。
- 当前列表存在非空提示词时，用户点击导入后必须再次确认。
- 用户取消确认或解析失败时，当前列表保持不变。
- 导入 23 条后只显示 23 行，不补足到 30 行。
- 用户仍可通过“新增一行”继续增加任务。
- 编辑器首次进入且没有任务数据时，现有的 30 个默认空行行为保持不变。

## 解析规则

### 结构化模式

1. 忽略第一个 `【页面编号】`之前的内容，例如文档总标题。
2. 每个以 `【页面编号】`开头的字段开始一条新记录。
3. 下一个 `【页面编号】`出现时结束上一条记录。
4. 字段标记按去除行首、行尾空白后的整行识别。
5. 每条记录必须包含页面编号、页面名称、生图提示词、画面核心文字和关键画面元素。
6. 同一份文本内页面编号不得重复。
7. 任务顺序与文本出现顺序一致，不按编号重排。
8. 清理每个字段的首尾空白，保留字段内部段落和换行。
9. 识别结果超过后端返回的 `maxBatchSize` 时禁止导入，不静默截断。

### 提示词组合

每条任务的 `prompt` 按以下格式生成：

```text
【生图提示词】
<生图提示词正文>

【画面核心文字】
<画面核心文字>

【关键画面元素】
<关键画面元素>
```

页面编号、页面名称和文档总标题不进入 `prompt`。

### 备注组合

每条结构化任务的 `note` 为：

```text
<页面编号> · <页面名称>
```

例如：

```text
封面 · 数学乐园重启计划——乘法的初步认识
P1 · AI数学乐园系统故障
```

### 简单逐行模式

- 每个非空行生成一条任务。
- 每条任务的 `prompt` 为该行去除首尾空白后的内容。
- `note` 为空。
- 超过 `maxBatchSize` 时禁止导入，不截断。

## 前端设计

### 解析模块

新增独立纯函数模块，将输入文本和单批上限转换为明确的解析结果：

```ts
type ImportedPrompt = {
  prompt: string;
  note: string;
};

type BulkImportResult = {
  mode: "structured" | "lines";
  items: ImportedPrompt[];
  errors: string[];
};
```

解析模块不读取 React 状态、不发请求、不写数据库，便于独立测试。

### 弹窗

现有批量粘贴弹窗调整为批量导入弹窗，负责：

- 保存用户粘贴的原始文本。
- 调用解析模块。
- 展示模式、数量、备注预览和错误。
- 在无错误时将 `{ prompt, note }[]`传回任务表。
- 当前任务存在内容时触发覆盖确认。

### 任务草稿与任务行

- `TaskDraft` 增加 `note: string`。
- 新建普通空行的备注默认为空字符串。
- 任务行顶部增加一个横向标题区域，在“第 X 张图”标签右侧显示备注。
- 备注使用次要的灰蓝色视觉样式；桌面端在同一行显示，窄屏允许换行。
- 备注为空时不渲染占位内容。
- 备注只读，不提供输入控件。

### 会话与历史恢复

- 编辑器本地会话自然保存 `TaskDraft.note`。
- 历史任务恢复为草稿时复制后端返回的 `task.note`。
- 旧会话或旧任务缺少备注时统一归一化为空字符串。

## 后端与持久化设计

### API

- 批次创建请求中的每条任务增加可选 `note`。
- 后端缺少 `note`时按空字符串处理，保持旧客户端兼容。
- 批次和历史任务响应返回 `note`。
- 子任务创建不新增备注交互，缺省保存空备注。

### 数据库

在 `tasks`表增加：

```sql
note text
```

迁移采用现有的启动时列检测方式：

- 新数据库的 `schema.sql`直接包含 `note`列。
- 旧数据库启动时通过 `pragma table_info(tasks)`检查。
- 缺少列时执行一次 `alter table tasks add column note text`。
- 读取到 `null`或缺失值时向前端返回空字符串。

该变更只增加可空文本列，不重写、删除或迁移现有任务数据。

### 远程生图请求

远程客户端调用继续只使用任务的 `prompt`、模型参数和参考图信息。`note`不加入 `ToApisClient.createImageTask`参数，也不拼接到 `prompt`。

## 错误处理

以下情况禁止导入，并在弹窗中给出明确错误：

- 没有识别到任何有效任务。
- 结构化记录缺少任一必填字段。
- 页面编号为空或重复。
- 页面名称为空。
- 三个提示词内容字段中任一为空。
- 识别数量超过 `maxBatchSize`。

错误信息应包含可定位的页面编号；页面编号本身缺失时使用记录序号。解析失败不会改变当前任务草稿。

## 测试设计

### 解析单元测试

- 识别封面和连续页面。
- 组合三部分提示词并保留段落与换行。
- 生成“页面编号 · 页面名称”备注。
- 忽略第一个页面记录前的文档标题。
- 保持文本顺序，不根据编号排序。
- 未出现结构化标记时按非空行导入，备注为空。
- 拒绝缺字段、重复编号、空内容和超过上限的输入。
- 结构化模式失败时不回退到逐行模式。

### 前端组件测试

- 入口显示“批量导入提示词”。
- 预览显示解析模式、数量和备注。
- 导入 N 条后任务表恰好显示 N 行。
- 备注显示在“第 X 张图”标签后。
- 当前存在非空提示词时出现覆盖确认。
- 取消确认或解析失败时任务列表保持不变。
- 初始无任务状态仍显示 30 个空行。

### 后端与持久化测试

- 批次创建请求能够保存并返回备注。
- 未传备注的旧请求仍可创建任务，并返回空备注。
- 旧数据库启动时自动增加 `note`列且原数据保留。
- 当前批次和历史恢复链路返回备注。
- 远程生图请求的提示词不包含备注。

## 验收标准

1. 粘贴符合约定的 23 页文本时，预览显示 23 条且备注正确。
2. 确认导入后任务编辑器只显示 23 行。
3. 每行提示词只包含三个生图内容字段，不包含页面编号和页面名称。
4. 每行标题区域显示对应页面备注。
5. 提交、刷新及历史恢复后备注仍然存在。
6. 远程生图请求不包含备注。
7. 错误格式不会覆盖现有任务。
8. 原有逐行导入仍可使用。
9. 项目完整测试与构建通过。
