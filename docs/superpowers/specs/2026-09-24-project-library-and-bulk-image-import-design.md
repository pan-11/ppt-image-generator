# 历史项目、新建项目与批量成品图导入设计

## 1. 状态、目标与范围

- 日期：2026-09-24；代码基线：`main` / `3a9aee1`，规划开始时工作区干净。
- 状态：用户已确认一张图片对应一页，并授权实施；实现和验证结果以工作日志为准。
- 目标：把当前工作台的一套课件可靠保存为历史项目，再新建独立项目，一次导入一批已生成的图片，继续选图、修改、去字和导出。
- 推荐解释：一个项目就是一套可继续编辑的课件；保存更新同一个项目，不在每次保存时复制一个历史版本。
- 已确认：上传的一张图片对应一页，导入后直接成为该页定稿。
- 已确认：无文字处理取当前项目中勾选页面的当前定稿图，新结果和处理记录归属当前项目；切换项目后面板显示该项目自己的处理记录。
- “保存在历史项目”指保存在当前电脑的应用数据中；项目打开后仍可编辑。此功能不提供跨电脑同步或独立备份文件。

## 3. 方案比较

| 方案 | 收益 | 代价与判断 |
| --- | --- | --- |
| A：完善当前课件管理，增加新建与批量图片导入 | 沿用现有工作台、图片、定稿和导出；用户能直接完成本次任务 | 改动集中，预计无数据库结构变更。推荐。 |
| B：另做项目首页和完整项目管理系统 | 将来适合大量项目的分类与管理 | 涉及导航及页面结构调整，当前保存和导入需求无需这么大范围。暂不采用。 |

采用 A。界面对用户使用“项目”称呼；内部继续使用 `courseware` 数据模型和 API，不批量重命名源代码。

## 4. 工作台入口

项目管理栏保持在当前工作台顶部，显示：

```text
项目名称                     已保存到本机 · 最近保存时间
共 23 页 · 已选定稿 23 页

[保存项目]  [新建项目]  [历史项目]
```

既有提示词库、PPT 导出、无文字版本入口继续放在现有工具区域。

### 保存项目

- 保存名称、全部已建立页面与页序、提示词、参考图设置、候选图关联、定稿选择、导出勾选；已关联的无文字记录继续保留。
- 未成功生图的页面也保留，避免保存后课件缺页。
- 已有项目更新原 ID；旧会话尚未建立课件时，先接管相关任务和页面，再完成保存。
- 自动保存继续生效，手动保存立即等待落盘并显示完成状态。无需重复创建“历史副本”。
- 保存不会重新生成图片，也不会复制一份相同图片文件。
- 保存失败显示原因并保留编辑内容；状态文案区分“正在保存”“已保存到本机”“保存失败”。

### 新建项目

点击后打开一个对话框，填写名称，并选择：

1. **从成品图片创建**：进入多图选择与导入预览。这是本次重点。
2. **空白项目**：创建零页项目，显示“上传成品图片 / 新增页面”。

默认名称为“新项目 + 本地日期时间”，可修改。原有批量导入提示词入口继续可用，创建课件前统一执行保存旧项目的流程。

空白项目内的“上传成品图片”将这批页面填入当前零页项目，沿用其名称和 ID，不另建一份。已有页面的项目仍通过“新建项目 → 从成品图片创建”导入另一套课件；首版不增加往非空项目批量追加页面的入口。现有单页添加候选图继续可用。

确认创建前关闭对话框，不产生新项目。确认后先保存旧项目，再创建新项目；只有创建成功或核实创建已成功，才切换工作台。

创建后的零页项目必须是真实、有独立 ID 的项目。应用不能把它当成没有会话而自动载入最近历史，也不能凭空补出五张默认页面。旧任务、结果缓存、参考图和未提交改图输入不得继承到新项目；模型、导出目录等通用偏好可以保留。

### 历史项目

由现有“打开课件”弹窗扩展，最近保存的项目排在前面。每项展示：

- 项目名称、首张已选定稿缩略图；无定稿时展示占位。
- 总页数、已选定稿页数、最近保存时间。
- 当前项目标记与“打开项目”操作。

打开前保存当前项目，成功后恢复目标项目的完整内容。“历史项目”用于找整套课件；原“生成历史”继续用于查看批次、错误和重试。两个入口的文案说明各自用途，不把旧生成批次伪装成重复的新项目。

项目列表使用现有课件记录，因此既有已保存课件直接可见。尚未转成课件的旧生成批次继续在生成历史中查看，打开并保存时复用现有接管逻辑。

## 5. 从图片创建项目

### 5.1 导入前预览

1. 用户多选或拖入图片，支持 PNG、JPEG/JPG、WebP。
2. 显示缩略图、文件名、显示方向下的尺寸、预计页码。
3. 初次按文件名自然排序，例如 `1.png → 2.png → 10.png`；同名按选入顺序稳定排列，不覆盖同名文件。用户可以上移、下移调整，并从待导入列表中移除图片；这不删除电脑中的原文件。
4. 项目名必须非空。一张图对应一页，页面名称默认取不含扩展名的文件名，提示词为空。
5. 单图沿用 20 MiB 上限；首版单次最多 `min(当前服务端 maxBatchSize, 100)` 页、合计 200 MiB，与现有页面和 PPT 导出限制衔接。
6. 在确认前检查空文件、格式、尺寸可读性和数量大小限制；后端仍完整解码并执行权威校验。列出具体文件错误，不静默跳过。

页面比例按图片显示方向识别；能匹配常用比例时使用规范比例，否则保留实际宽高比例。沿用已有像素取整容差，避免将实际同为 16:9 的相邻像素尺寸误判成不同比例。

混合比例图片可以导入同一项目，预览明确显示哪些页比例不同，并提示整套导出时需要选择同比例页面。导出仍执行已有混合比例拦截，不自动裁切或拉伸。模型不支持某比例，只影响后续生成操作，不影响上传、查看和符合比例条件的 PPT 导出。

### 5.2 创建与上传

确认按钮显示“保存当前项目并创建”，没有当前内容时显示“创建项目并导入 N 张图片”。

以下流程对应直接从图片创建新项目。若从当前零页项目进入，按钮为“导入 N 张到当前项目”，先保存当前项目，再使用 revision 检查添加有序页面，保留原项目 ID；之后的上传和恢复规则相同。

```text
校验预览清单
    → 保存当前项目
    → 创建新项目与有序页面
    → 切换到新项目
    → 逐页上传原文件
    → 每成功一页即保存候选与定稿
    → 显示完成数和失败项
```

- 项目 ID、pageId、每个文件的 uploadId 在此次确认时固定。重复点击或重试使用相同身份，防止创建重复项目、页面或候选图。
- 页面身份与顺序在上传前确定，上传完成时间不能影响页序。
- 首版串行上传，复用现有 revision 和上传队列。对本地服务器逐张提交即可，不增加并行写整份课件带来的冲突。
- 上传使用成品图接口，成功后设为该页定稿、默认参与导出；原始文件字节按现有存储机制保留。
- 页面显示“外部上传”和实际尺寸。生成模型、输出分辨率等仅作为未来生成设置，不声称是原图的生成参数。
- 上传本身不会调用生图服务或产生远程生成任务。用户明确发起改图、去字时才进入现有生图流程。
- 无文字入口只提交当前项目的页面和定稿，服务端校验图片归属并将去字记录、任务关联回当前项目；列表按当前项目读取，切换后不能显示另一项目的记录。
- 没有原始提示词时允许保存、排序、选图和导出；文生图按钮需要补充提示词后才能使用。改图使用上传图与新编辑指令，去字使用现有模板。

### 5.3 进度、失败与中断

- 展示“正在导入 8/23”“已成功 21，失败 2”，每个失败项对应准确的页码、文件名和原因。
- 明确校验失败可继续处理后续图片；失败页保留占位，允许单独重选或重试。成功页不重传、不清空，导出时不静默遗漏占位页。
- 若上传响应丢失，先查询该项目中是否已有同 uploadId 的候选；确认已成功就使用该结果。无法确定时暂停后续写入，复用同 ID 重试，不盲目用旧 revision 继续。
- 上传进行中暂时禁用项目切换和会改动同一项目的编辑操作，预览可用；可以“停止后续上传”，等待当前请求结果确定后再开放切换。已完成页面保留，不自动撤销数据。
- 页面刷新或关闭后，已经上传的页面从服务器恢复。未上传的本地文件需重新选择，不承诺浏览器关闭后继续上传。
- 为便于续传，在浏览器保存按项目 ID 区分的导入清单元数据：pageId、uploadId、文件名、大小、修改时间、顺序和状态；不存图片二进制。恢复时以服务器的图片记录核实成功项，仅对未完成项请求重新选择文件。
- 重选匹配只作为提示，展示目标页与文件供用户检查；同名或信息冲突时不自动猜测。若原文件已更换，按一次新的候选上传处理，不能复用可能已成功的旧 uploadId。
- 创建请求响应丢失时，也先按固定项目 ID 核实；查询失败保留创建草稿并停留当前项目，待重试，不立即再建一份。

## 6. 保存和切换的共同约束

新建、打开历史项目、从提示词新建、从图片新建四个入口共用同一保存与切换流程。

1. 有正式项目则等待自动保存和正在提交的本地写入完成；未建项目的旧会话若有提示词、备注、参考图、任务或图片，则先完整保存。原始空白工作台不额外制造一个空历史项目。
2. 保存必须覆盖当前有明确关联的所有页和结果，不能只保留最后一个 activeBatch。旧会话接管后逐页核对 task/page 关联；无法确认归属的内容不得丢弃或强行归到其他项目，应阻止切换并保留当前内容。
3. 普通保存失败、revision 冲突、结果未确认的上传均阻止切换，用户可重试或先处理冲突；不提供默认丢弃草稿的路径。
4. 切换成功一次性安装新项目的页面、详情和会话标识，重置旧结果、参考图、编辑弹层和批次监听上下文。
5. 所有异步回调核对项目 ID、页面 ID 与本次打开序号；已切走项目的旧响应不能覆盖新页面。现有批次轮询尤其需要在更新状态前校验，而不能只在更新后停止定时器。
6. 已提交到后台的生图任务可以继续执行，结果仍关联原项目；新建或切换不会取消、重新提交旧任务，也不自动暂停整个生成队列。
7. 刷新优先恢复当前项目，包括零页项目；不得用旧编辑器缓存或最近批次覆盖它。

## 7. 实现边界与数据方案

预计无需新增表、列或迁移。复用：

- `coursewares`：项目名称、页面 JSON、revision 和保存时间。
- `courseware_task_links`：生成任务属于哪一项目、哪一页。
- `courseware_uploaded_images` 和已有文件存储：成品图关联及 uploadId 去重。
- 上传新项目使用已有 `sourceKind: manual`，`rawImportText` / `importMode` 为空；图片通过 `source: upload` 表达真实来源。
- 已有课件创建、更新、详情、接管历史和逐页成品上传接口。

项目列表接口可按需增加 `coverImageId`、`selectedPageCount` 等派生摘要，不增加持久化列。缩略图只使用受控图片 ID 和既有读取接口；缺失封面显示占位，不影响打开项目。列表不为每个项目加载整套图片。

组件与职责：

| 范围 | 责任 |
| --- | --- |
| 现有 `courseware-toolbar.tsx`、`courseware-list-modal.tsx` | 项目入口、保存状态和历史列表。 |
| 拟新增 `new-project-modal.tsx`、`bulk-image-import-modal.tsx` | 新建方式、文件预览、排序、进度与重试入口；放在现有 `web/src/components/courseware/`。 |
| `App.tsx` 与 `use-courseware.ts` | 所有入口共用保存后切换；空项目、旧会话接管和异步隔离。只抽取此次确实共用的流程，不重写整个 App。 |
| 导入队列与文件清单小模块 | 固定身份、顺序上传、错误分项与浏览器恢复元数据；复用上传 hook。 |
| `task-table.tsx`、必要的 `task-row.tsx` 变化 | 零页空态与纯图片页面显示；既有单页生图和候选操作继续复用。 |

## 8. 验收标准

| 编号 | 操作 | 预期结果 |
| --- | --- | --- |
| A1 | 当前多页课件含原图、改图、定稿和无文字结果，保存后新建，再从历史打开 | 页面、顺序、全部候选、选中版本、提示词和无文字来源关系正确，图片字节未变。 |
| A2 | 当前项目有新增编辑，保存接口失败后点击新建或打开其他项目 | 留在当前项目，保留输入，没有虚假的保存成功提示。 |
| A3 | 新建零页项目并刷新，再从空态批量上传 | 刷新后仍是该空项目，无旧图片、旧参考图、旧任务或自动补出的五页；上传沿用其名称和 ID，不额外建项目。 |
| A4 | 导入 `1.png`、`10.png`、`2.png` 并调整顺序 | 自然排序正确；手动调整后按预览顺序建页、保存和导出。 |
| A5 | 导入 23 张同一比例的有效图，不提供提示词 | 建立 23 页与 23 张上传定稿，能重新打开和导出；零远程生图调用。 |
| A6 | 某张损坏、超限或格式不符 | 指出准确文件；已成功页保留，失败页可重试，不静默缺页。 |
| A7 | 上传已提交但响应丢失，或双击创建/重试 | 按固定 ID 核实与重试；没有重复项目、重复页面或重复候选。 |
| A8 | 导入中停止或刷新，再重新打开 | 已成功页恢复，未完成页明确显示；重选文件后只处理未完成项。 |
| A9 | 当前项目后台生图尚未完成时新建，旧轮询稍后返回 | 后台结果进入原项目，新项目保持独立。 |
| A10 | 保存同一项目多次，随后打开历史项目列表 | 只有同一条项目记录更新；封面、页数和时间正确；旧课件仍可找到。 |
| A11 | 上传图片尺寸有正常像素取整差异，另有明显不同的比例 | 正常取整按既有容差通过；明显混合比例可预览导入，整套导出明确拦截，不变形。 |
| A12 | 上传图没有提示词，随后选择修改或去字 | 查看/保存/导出无需提示词；显式发起生成才使用现有模型校验、队列与来源关联。 |
| A13 | 两个标签页修改同项目，或保存旧会话包含跨批次结果 | revision 冲突不覆盖另一窗口；不能只保存最后一批或丢失已有候选。 |
| A14 | 桌面和窄屏，用键盘完成创建、排序与打开 | 主要操作可达、进度可读、焦点正常、没有横向溢出。 |
| A15 | 在新导入项目 B 生成无文字版，再切回旧项目 A | B 的当前定稿是去字源图，记录和结果只出现在 B；A 原有记录不变。 |

实施按三段验收：
