# 正式生图中转站设置页设计

日期：2026-08-11

## 目标

为图片生成项目增加一个正式的中转站设置页。用户可以在本机保存多个中转站配置，选择其中一个作为“当前使用”，之后新提交的正式生图任务统一使用该中转站。

## 范围

设置项仅包含：

- 名称
- Base URL
- API Key
- 备注

配置列表提供“编辑”和“设为当前使用”操作，并明确标出当前正式生图使用的中转站。

## 不在本次范围

- 不为每条任务单独选择中转站。
- 不自动故障转移到备用中转站，避免失败时重复扣费。
- 不删除中转站配置。
- 不修改数据库结构，不迁移历史任务。
- 不修改 `.env`。
- 不改变模型、比例、分辨率、并发数和批次上限设置。

## 现状

项目已有 `/settings` 页面，但它是“中转站实验室”，用于保存测试配置、运行单张基准测试和查看对比记录。实验室配置保存在 `app-data/lab/`，按照项目隔离规则不能直接用于正式生图。

正式生图目前由 `BatchService` 使用启动时从 `.env` 读取的 API Key，并通过默认 ToAPIs Base URL 创建客户端。

## 页面设计

`/settings` 改为正式的“中转站设置”页面，并在生图工作台顶部把入口名称从“中转站实验室”改为“中转站设置”。

页面从上到下包含：

1. 当前正式生图使用的中转站摘要，显示名称、Base URL 和 Key 掩码。
2. 添加或编辑中转站表单，包含名称、Base URL、Key、备注和保存按钮。
3. 已保存中转站列表，显示名称、Base URL、Key 掩码、备注、当前使用状态，以及编辑和“设为当前使用”操作。

新增配置时 Key 必填。编辑配置时 Key 留空表示保留原 Key。页面和接口永远不返回完整 Key。

现有实验室页面和后端基准测试能力保留，但不再作为 `/settings` 的主体，也不进入本次正式配置数据流。

## 本地存储

正式中转站配置保存在：

`app-data/provider-settings.json`

该文件属于本地运行数据，继续由现有 `.gitignore` 规则排除，不进入 Git。

文件包含：

- `activeProviderId`：当前使用的中转站 ID；未设置时为 `null`。
- `providers`：中转站配置数组。

每个中转站包含 ID、名称、Base URL、API Key、备注、创建时间和更新时间。API Key 在本地文件中保存明文，因此接口只能返回 `hasApiKey` 和末四位掩码。

如果没有选中的正式中转站，正式生图继续使用现有 `.env` 配置作为回退，保证升级后原有工作流不被中断。

## 后端组件

新增独立的正式配置存储服务，职责为：

- 读取和写入 `provider-settings.json`。
- 校验名称、Base URL、Key 和备注。
- 返回脱敏后的配置列表。
- 保存新增或编辑后的配置。
- 持久化 `activeProviderId`。
- 返回当前正式生图应使用的完整服务端配置。

该服务与 `server/src/lab/` 保持隔离，不读取或写入 `app-data/lab/`。

## API 设计

新增正式设置接口：

- `GET /api/provider-settings`：返回脱敏后的配置列表、当前使用 ID，以及是否正在使用 `.env` 回退。
- `POST /api/provider-settings`：新增中转站。
- `PUT /api/provider-settings/:providerId`：编辑中转站；省略或留空 Key 时保留旧值。
- `POST /api/provider-settings/:providerId/activate`：设为当前使用。

不提供删除接口。

## 正式生图数据流

1. 用户在设置页保存一个或多个中转站。
2. 用户点击“设为当前使用”。
3. 后端确认当前没有排队、提交、生成或下载中的正式任务。
4. 后端更新 `activeProviderId` 并返回新的脱敏状态。
5. 后续正式生图任务执行时，从正式配置服务获取当前中转站并创建对应的 `ToApisClient`。
6. 如果没有 `activeProviderId`，继续使用 `.env` 中的现有 Key 和默认 Base URL。

切换中转站时如果存在活动任务，接口返回冲突错误，页面提示用户等待当前任务完成后再切换。这样不需要修改任务数据库，也不会让同一批次在执行过程中切换中转站。

## 校验与错误处理

- 名称去除首尾空格后不能为空。
- Base URL 必须是有效的 `http` 或 `https` URL，并移除末尾斜杠。
- 新增时 Key 去除首尾空格后不能为空。
- 编辑时空 Key 表示保留，不覆盖原值。
- 备注限制为 2000 个字符。
- 目标中转站不存在时返回 404。
- 存在活动任务时切换返回 409。
- 本地配置文件格式无效或写入失败时返回明确错误，不修改当前内存状态。
- 中转站请求失败时沿用现有任务失败和重试逻辑，不自动切换到其他中转站。

## 安全边界

- 完整 Key 只在服务端接收和本地保存。
- Key 不进入日志、错误信息、测试快照或 Git。
- GET、POST、PUT 和 activate 接口响应都只返回掩码。
- 不读取或修改 `.env`。
- 不把正式配置写入实验室目录。

## 测试计划

后端测试覆盖：

- 新增配置并持久化。
- 返回 Key 掩码且不泄露完整 Key。
- 编辑时空 Key 保留旧值。
- 设置和重启读取当前中转站。
- 空闲时允许切换。
- 有活动任务时拒绝切换。
- 正式生图使用当前中转站的 Base URL 和 Key。
- 未选择中转站时回退 `.env`。

前端测试覆盖：

- `/settings` 渲染名称、Base URL、Key 和备注表单。
- 新增和编辑操作正确提交。
- 当前使用状态正确显示。
- “设为当前使用”成功后刷新状态。
- 活动任务冲突和普通保存错误显示清楚。

回归和人工验证：

- 运行 `npm test`。
- 运行 `npm run build`。
- 验证批量生成、单行生成、历史恢复和子图生成不受影响。
- 在桌面和手机宽度检查 `/settings`，确保字段、按钮和长 Base URL 不溢出。

## 实施约束

实施前先更新项目 `AGENTS.md`，补充正式中转站配置目录和隔离规则，再修改代码。保留当前工作区已有未提交改动，不回滚、不覆盖，也不把 `.env`、`app-data`、图片或数据库文件加入提交。
