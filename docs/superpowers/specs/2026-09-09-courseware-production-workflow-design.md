# 课件提示词、定稿与 PPT 导出设计

## 状态与范围

- 日期：2026-09-09。
- 状态：待用户确认的完整设计；编写本文件不代表允许实施、改数据库或发起收费生图。
- 代码基线：本地 `main` 的 `92eaa1d`，包含子图显示与历史恢复修复。
- 本轮覆盖：批量导入提示词留存与复制导出、每页定稿选择、图片 PPT 导出、逐页去字、无文字图片 PPT 导出。
- 用户已明确：原图和子图属于同一页，导出时只能选一个版本。
- 推荐补充规则：一条任务行是一页；该行多张原始结果及全部后代图均为候选版本。
- 无文字处理提示词原文保存在 `docs/textless-background-prompt.md`，后续实现必须使用这份完整文本。

## 方案选择

| 方式 | 改动与收益 | 局限 |
| --- | --- | --- |
| 只在导入弹窗、普通子图和图片下载处增加按钮 | 改动较少，能快速复制当前文本或手动生成去字图 | 无法可靠保存整份原文、跨批次页面身份和定稿对应关系 |
| 增加本地课件记录，共用现有生图引擎与一个 PPT 导出器 | 统一保存提示词、页序、定稿和去字来源；分阶段交付 | 需要新增少量本地数据库记录和关联逻辑 |

采用第二种。课件用于组织用户的一套页面；现有生成批次继续负责一次生成作业。单页重生成可以产生新批次，但仍属于原来的课件页面。

## 使用流程

1. 批量粘贴提示词，查看解析预览，确认导入。
2. 自动保存一份课件：保留整份导入原文，并建立具有稳定 ID 的页面草稿。
3. 按现有方式生图、生成子图。修改页面提示词会更新草稿，不覆盖导入原文或历史生成提示词。
4. 每页选择一张定稿图。
5. 可复制或导出提示词，也可导出定稿 PPT。
6. 对已选定的页面批量生成无文字版本，查看对照、处理失败页或重新处理单页。
7. 按同一份页面清单导出无文字 PPT。

## 提示词保存与复用

### 保留的内容

| 内容 | 保存规则 | 用途 |
| --- | --- | --- |
| 导入原文 | 保存应用收到的完整粘贴文本；不 trim、不重新拼接、不丢弃总标题与字段；此后保持不变 | 复制原文、导出 TXT/Markdown、按原有格式再次使用 |
| 当前页面提示词 | 保存每页最新草稿，保留正文的段落、换行与空白 | 单页复制、按当前页序复制全部、导出 TXT/Markdown |
| 图片的实际生成提示词 | 复用现有 `tasks.prompt` 历史记录；已提交任务的提示词不随草稿修改而变化 | 从候选图查看和复制其当时使用的提示词 |

“当前提示词”中的每页正文就是编辑器里该页的完整内容，包括已有的画面核心文字、关键画面元素等字段；不只导出其中一个字段。

选定子图不覆盖页面的基础生图提示词。子图旁复制的是它实际使用的编辑指令，并提示该指令需要配合参考图使用；不能把它冒充一条能够独立复现整页的文生图提示词。去字模板也不混入基础生图提示词导出。

### 入口与导出格式

- 在“批量导入提示词”旁增加“提示词”入口，复用现有 `ModalDialog`。
- 弹窗提供“导入原文”“当前提示词”两个视图。
- 导入原文视图：只读预览、复制原文、导出 TXT、导出 Markdown。
- 当前提示词视图：按页预览、复制本页、复制全部、导出 TXT、导出 Markdown。
- 每个任务行同时提供“复制提示词”，复制该行正文，不额外加入编号或参数。
- 复制全部和当前文件导出带页序与页面名称，以便在其他工具中区分页面；正文原样置于各页内容块中。
- 导入原文导出不添加包装标题；文件内容与保存的原文一致。
- 当前 TXT/Markdown 是供人阅读与复用的按页文本；本期不将任意 Markdown 导出声明为现有五字段解析器的无损回导格式。需要原格式回导时使用“导入原文”。
- 默认导出当前课件全部页面的提示词；PPT 的页面勾选不会删去提示词档案中的页面。
- 文件使用 UTF-8；生成英文文件名，例如 `courseware-<id>-import-original.txt`、`courseware-<id>-prompts-current.md`。
- 文件下载沿用浏览器下载机制；仅复制或导出文本不会调用生图服务。

浏览器剪贴板写入可能被拒绝，成功提示必须在 `writeText` 完成之后显示。失败时保留可选中的完整文本，提供手动复制方式，不显示虚假的“已复制”。依据：[MDN Clipboard.writeText](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard/writeText)。

### 保存时机与旧数据

- 成功导入就写入本地数据库，即使没有生成图片，也能在“打开课件”中再次找到。
- 每次新导入建立一份新课件；当前课件先保存，再切换。原有课件不被新原文覆盖。
- 解析失败、取消导入或服务端保存失败时，不替换当前页面，不丢掉当前输入文本。
- 编辑暂停约 500ms 后自动保存最新草稿；请求串行发送，避免较早的保存请求覆盖较新的输入。
- 显示“保存中／已保存／保存失败”。失败时保留浏览器草稿和复制导出入口，不声称已落盘。
- 服务端保存使用 revision 防止多个标签页相互覆盖；冲突时保留当前草稿，提示重新载入或先导出文本。
- 老会话和老批次只有已解析的 `prompt`、`note` 时，保留并支持当前提示词导出。原文栏显示“此记录未保存导入原文”，不伪造原文。
- 不批量改写旧记录。用户打开历史记录时，才建立课件与旧任务的关联；再次打开同一历史批次应复用已建立的课件。

## 页面与定稿

- 每页具有稳定 `pageId`；页身份不依赖当前 `submittedTaskId`、图片文件名或批次 ID。
- 新增或复制任务行创建新 pageId；复制只带入提示词及参数，不把原页的定稿和历史任务身份当作新页的结果。
- 页面排序取课件页面清单中的 `position`。不按生成时间，也不对“封面、P1、P10”等显示编号进行字符串排序。
- 原始任务、同页重新生图任务、子图和孙图全部关联同一 `pageId`。
- 每页一个 `selectedImageId`，因此所有候选版本互斥。
- 尚无定稿时可默认选中首张校验通过的原始结果；后续候选到达不替换已有定稿。用户可手动更换。
- 无有效结果的页面保持占位，展示缺图原因；不静默少导一页。
- 勾选决定这一页是否参与本次 PPT，单选决定这一页使用哪个版本；两个操作语义独立。
- 定稿选择与页序保存在课件中，刷新或恢复历史后仍可恢复。
- 当前课件的全局参考图 ID 一并保存；恢复课件时不能沿用另一份课件的全局参考图。
- 若历史图片缺少新式校验记录，先做文件和尺寸检查并要求明确选图；不把旧校验失败的残留文件自动当作成功定稿。
- 图片或任务被现有删除流程移除后，课件保留页面及提示词，缺失的候选或定稿显示不可用；导出被阻止，不能偷偷换用另一张图。

## PPT 导出

- 新增一个后端 `pptx-service.ts`，定稿版与无文字版共用。
- 输入是已解析并验证的有序页面列表。客户端提供页面和图片 ID，服务端验证归属、存在性、结果状态，禁止以客户端文件路径读取任意文件。
- 每页只有一个完整图片对象，图片从页面左上角铺满；不添加标题、页码或自动文本框。
- PPT 内嵌图片，不依赖网络图片 URL。PNG/JPEG 尽量保留原始字节；WebP 等需转换时在内存转为 PNG，保持画面及像素尺寸，原始文件不被替换。
- 使用图片实际宽高及显示方向确定比例，而不是仅信任任务的 `16:9` 标签。
- 一份演示文稿采用统一页面尺寸。默认跟随所选图片的共同实际比例；不同分辨率但相同比例可以放在同一文件。
- 混合比例或方向不一致时列出异常页，默认阻止导出。第一版不悄悄裁切、拉伸或改用留白模式；用户需调整所选页面或分次导出。
- 对于仅像素取整造成的细微比例差异，也不得未经展示就变形。显示具体尺寸，由用户选择同比例版本后继续。
- 开始导出时固定本次页面与定稿 ID 清单；导出期间的 UI 操作不改变正在生成的文件。
- 无文字批次保存自己的来源清单，可以从该清单分别导出定稿版与无文字版，保证前后两套页数、页序和源图版本匹配。
- 下载文件名包含课件 ID、类型和导出时间，分别为 `final` 与 `textless`；返回标准 PPTX MIME 类型。
- 导出服务每次处理一份文件，并在读取所有图片前校验页数、格式和资源总量；建议初始上限 100 页、原图总字节 200 MiB，超出时提示分次导出。

PptxGenJS 支持本地图片、自定义统一页面尺寸与 Node Buffer 输出，适配现有 Node/Fastify 后端。[图片接口](https://gitbrent.github.io/PptxGenJS/docs/api-images/)、[页面尺寸](https://gitbrent.github.io/PptxGenJS/docs/usage-pres-options/)、[输出接口](https://gitbrent.github.io/PptxGenJS/docs/usage-saving/)。

## 无文字版本

- 每次批量处理建立独立的 `textlessRun` 和生成批次，共用现有图生图适配器与 provider 队列；不把去字任务追加到原图批次。
- 处理前展示本次页数、所选图生图模型和各页比例／分辨率；每页参数必须通过当前通道能力校验。
- 每页使用选中的定稿图、完整去字提示词，`n = 1`；不拼接整套图片，不叠加原始文生图提示词。
- 提交时保存页面顺序、源图片 ID、提示词全文、模型与规格快照。写入作业关联后才允许队列发单。
- 无文字结果通过本次任务关联到精确源图片 ID，不通过“最新图片”或“同一批次”猜测来源。
- 换定稿后，旧无文字结果仍归旧定稿。切回原来的候选可复用已有匹配结果；新版本没有匹配背景时显示未生成。
- 已发出的去字请求不随定稿切换而变化，完成结果不能挂到刚选的新版本上。
- 失败只重试相应作业，成功页不重做。远端状态未知时继续使用现有扣费风险确认。
- 重新处理效果不满意的成功页，建立一次新的单页处理记录，以该页定稿为输入；保留旧结果，不拿旧去字图继续擦除。
- 自动检查可读格式、像素尺寸、比例及文件完整性；文字残留、插画变形等语义质量由原图／去字图对照验收，不声称完全无损。
- 无文字 PPT 缺少选定页面的可用结果时明确列出缺页，不混入带字图片。
- 已完成成果可在服务重启后恢复。未完成的新去字任务需按保存状态恢复：未提交任务重新排队，有远端引用的任务恢复查询或下载，无引用而可能已提交的任务转为 unknown；不能自动重新付费发单。
- 原有全局暂停语义保持一致，不新增看起来只暂停去字、实际暂停所有生成的误导按钮。

## 推荐持久化边界

推荐新增四张表，保留现有生成表作为作业和图片事实来源：

| 新表 | 责任 |
| --- | --- |
| `coursewares` | 课件名称、不可变导入原文、来源类型、页面草稿与定稿选择 JSON、保存 revision |
| `courseware_task_links` | 将现有任务绑定到课件、稳定页面，以及原始／变体／去字用途 |
| `textless_runs` | 固定一次去字操作的页面来源清单、模型参数和提示词快照 |
| `image_job_results` | 显式关联图片、作业、尝试序号和尺寸校验结论，避免误用失败尝试留下的图片 |

把小规模课件草稿保存在经过验证的 JSON 中，避免为了编辑器每一个字段都增加数据库列；跨作业查询所需关联独立存表。数据仍保存在现有本地 SQLite 和图片目录，不创建第二套图片存储。

这些新增表属于用户要求必须确认的 schema 变更。实现前需批准表清单；第一次在真实数据库运行前备份并检查迁移结果。本轮不修改 schema、不连接真实数据库进行迁移。

## 页面入口

工具栏按用途放置：

- 文本区域：`批量导入提示词`、`提示词`、`打开课件`。
- 结果区域：`导出定稿 PPT`、`生成无文字版`、`导出无文字 PPT`。
- 单页区域：复制本页提示词、候选图单选、原图／无文字图对照、失败重试或重新去字。

复用已有对话框、历史区域和任务组件，不重做首页视觉风格，也不引入独立 PPT 编辑器。

## 分期与成功标准

| 阶段 | 可交付成果 | 必须验证 |
| --- | --- | --- |
| A 提示词档案 | 未生图也能保存课件，复制和导出原文／当前提示词 | 中文、多段落、原文保真、修改后两份内容互不覆盖、重启恢复、保存失败与复制失败 |
| B 每页定稿 | 稳定页面、跨批次版本归属、每页单选与恢复 | 原图/子图/孙图互斥，重生成不增页，新图不抢定稿，缺图不跳页 |
| C 定稿 PPT | 一页一图、有序、内嵌且铺满 | 乱序完成不乱页，相同比例不同分辨率，混合比例拦截，Office/WPS 打开 |
| D 无文字流程 | 独立处理、来源对应、单页重试、匹配的无文字 PPT | 每请求一个来源与一个输出，切换定稿不串图，部分失败不重复生成，重启恢复不重复发单 |

每阶段运行相关测试；阶段收尾和最终交付运行 `npm test`、`npm run build`。真实去字效果验证应先选择文字密集、表格、插画各一页，另获真实调用授权后再执行；不自动对整套课件收费测试。

## 本期边界

- 输出 PPT 每页是图片；后续可在无文字版上添加文本框。本期不包含 OCR 和自动还原可编辑文字。
- 不接入新中转站，不更换现有密钥或 `.env`，不增加全局依赖，不部署或推送仓库。
- 不清理或覆盖原图、旧生成记录和导入原文。
- 不推断旧记录中已经丢失的导入原文或无法证明的页关联。
- 不提供自动去字质量评分或反复生成直到“满意”的收费循环。
