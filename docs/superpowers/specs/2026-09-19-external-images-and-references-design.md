# 外部成品图导入与参考图入口设计

日期：2026-09-19。版本：具体设计 v1（2026-09-20 实施记录补充）。用户已明确要求按本方案开始执行，包含下述增量数据库扩展与升级前备份。成品图作为定稿、改图保留原图并追加参考图均已确认。

## 1. 目标与已确认行为

用户需要把其他工具制作的图片加入当前课件，并在批量导入提示词、批量生成、编辑提示词后重新生成、修改图片时直接上传参考图。

已确认的成品图行为：上传图加入指定页候选列表，默认选为定稿，原图与改图继续保留；保存、重新打开和导出 PPT 都使用记录的选择。

已确认的改图行为：保留正在修改的原图，将新上传的参考图一起交给 AI。例如保留原图的页面布局，用上传图提供角色形象。

## 2. 本轮建议范围

| 入口 | 操作与结果 |
| --- | --- |
| 页面候选图片区 | 增加“上传成品图”。选择本机图片后显示“上传图”，自动设为本页定稿，旧候选可继续切换。 |
| 批量导入提示词 | 弹窗增加“本批共用参考图”，导入后各页默认使用它；参考图不写入提示词正文。 |
| 批量生成 | 在生成按钮附近提供“共用参考图”设置弹窗，工具栏下方展示当前共用图摘要，支持上传、更换、取消使用。现有页面可应用共用图，已有单页专用图保留。 |
| 编辑提示词后重新生成 | 提示词旁显示实际生效的参考图，支持“共用参考图 / 本页专用图 / 不使用参考图”，编辑完成后按这些输入生成。 |
| 修改图片 | 显示固定的原图，以及可上传、更换、取消使用的补充参考图；原图排第一，补充图排第二。生成结果加入同一页候选列表。 |

第一版沿用每页一张自定义参考图的现有范围；“修改图片”可同时使用原图与一张补充图。批量共用和单页专用二选一，避免意外叠加图片；只有改图入口明确组合原图与补充图。

共用图只自动影响“跟随共用图”的页面，保留“本页专用图”和“不使用参考图”的选择。新增或新导入页面默认跟随共用图；共用图为空时实际按文生图处理。旧页面原有模式保持不变。共用图设置中提供默认不勾选的“将未使用参考图的 X 页也改为跟随”选项，明确列出影响页数。单纯打开设置不修改页面。

所有上传入口显示缩略图和上传状态；上传失败可在原处重试，上传未完成时阻止依赖该图片的生成。取消使用只解除当前草稿的关联，不删除文件或历史任务的参考图。

## 3. 现有代码依据

- `web/src/components/tasks/defaults-bar.tsx` 已有全局参考图上传；`task-row.tsx` 已有单页上传，但这些控件在参数区域内。
- `bulk-paste-modal.tsx` 只传递提示词文本与解析结果，未承载参考图；提示词编辑区域也未展示当前生效的参考图。
- `web/src/lib/api.ts` 的子图请求没有上传参考图字段；`server/src/services/batch-service.ts` 在创建子图时强制使用所选原图。
- 适配器统一输入已经是 `ReferenceAsset[]`。本地 GrsAI 适配器测试包括两张参考图编码；这证明本地请求构造具备基础，不代表本轮已完成实际中转站验证。
- 数据库任务目前只有一个 `reference_image_id`；课件候选、下载、改图和去字目前都依赖生成图片记录与任务关联。

## 4. 数据与实现方案

采用明确记录外部上传来源、复用现有参考图文件存储的方式。

可选方案比较：把上传图片挂到新建的本地任务上可以少改部分查询，但会混入生成历史与统计；使用独立的上传关联记录能准确表达来源，也无需为成品上传创建生图任务。推荐后者。

拟做两项本地数据库结构扩展：

1. 新增 `courseware_uploaded_images` 表：`id` 与唯一 `upload_id` 使用本次上传 UUID，`reference_image_id` 关联独立的 `reference_images.id`，另存 `courseware_id`、`page_id`、实际宽高和创建时间。图片字节复用现有本地参考图存储，页面候选通过该表关联。独立上传 ID 使响应丢失后的重试可以找到已提交记录。
2. 为 `tasks` 新增可空的 `auxiliary_reference_image_id` 字段。原 `reference_image_id` 继续记录主要参考图；子图任务记录原图副本为主要参考图，新上传图片为补充参考图。旧任务补充字段为空，行为保持兼容。

数据库扩展须先取得用户明确授权。实施时先生成并验证一致性备份，再执行幂等、串行的增量结构升级。备份保留在本地，命名及保留规则先加入项目规范。既有任务无需改写成新格式。

### 外部成品图

- 上传接口校验课件、页面、文件实际格式、完整解码和宽高；图片比例沿用现有 PPT 兼容规则，与目标页不符时在上传处说明，不自动裁剪或拉伸。
- 使用生成图片与上传图片的统一候选查询结果，显式标记来源。上传图没有本站生成任务或生成提示词，界面保留本页原有提示词，候选处不冒充其生成来源。
- 上传成功后关联目标页并保存定稿选择，沿用课件 revision 检查，避免迟到的上传响应覆盖另一份课件或其他刚保存的编辑。
- 下载和 PPT 导出读取上传的原始字节；上传动作不调用中转站。
- 上传图可以作为之后“修改图片”和已有“无文字版本”的源图。缺少生成任务时，使用该页已保存参数与图片实际尺寸校验，不能要求它存在一个伪造的历史生成任务。

### 参考图与任务

- 复用现有本地参考图上传服务，补充供界面显示缩略图和文件名的读取入口。
- 批量导入时同时保存共用参考图和页面引用；重新打开课件恢复相同图及模式。
- 修改提示词重新生成沿用当前页实际生效的参考图；换图只影响之后新提交的任务。
- 子图草稿通过 API 传递补充参考图 ID。任务持久化两个 ID，提交和重试均恢复相同顺序、相同字节的输入。
- 派发继续依据是否包含参考图使用当前图生图中转站；已提交远程任务保留原 provider/revision。沿用单输出单任务及部分失败重试规则。
- 适配器收到完整的参考图数组。对当前模型不支持的输入在提交前明确报错，不忽略补充图；实施时核对受影响适配器的官方契约和已有测试。
- 子图草稿继续采用现有编辑面板生命周期；已提交任务的原图与补充图必须持久保存。

## 7. 界面与操作的具体设计

### 7.1 工作台布局与命名

保留目前“左侧页面信息—中间候选图片—右侧操作”的布局。蓝色继续表示主要操作与已选定稿；参考图缩略图使用浅灰容器，不使用定稿单选框。

交互选择：推荐“候选区上传成品 + 行内编辑单页 + 弹窗管理共用图”。把所有上传控件一直展开会增加每页高度；统一放进独立素材库又会增加操作步骤。本方案把入口放在实际使用图片的位置，上传与确认在同一上下文完成。

顶部任务工具栏：

```text
页面任务          [批量导入提示词] [共用参考图 · 已设置] [批量生成（23 页）]
```

每页示意：

```text
01  封面      [原图1]  [改图2]  [上传图1]  [＋ 上传成品图]   [生成这页]
16:9 · 1K       ○        ○       ● 已选定稿                 [编辑提示词]
参考：共用图   修改图片  修改图片  修改图片                   [页面参数]
```

- “上传成品图”始终位于该页候选列表末尾，未生成过的页面也有入口。
- 原图、改图、上传图分别计数，例如“原图1 / 改图1 / 上传图1”，编号随保存记录稳定恢复。
- 每页增加简短的参考状态：“参考：共用图”“参考：本页专用”“参考：无”。点击状态打开本页提示词和参考图编辑区。
- 单页提示词修改与修改图片继续在当前行展开，其他页面保持紧凑。每页同一时间只展开一个编辑区。
- 生成任务状态和定稿来源分别展示：手动上传可形成有效定稿，但不把之前失败的生图任务改写成成功。历史错误保留在折叠详情中。
- “上传成品图”和“上传参考图”保持不同文字与位置，避免把素材误当成最终页。

### 7.2 上传成品图：替换这一页的定稿

1. 点击候选区末尾的“上传成品图”，选择本机文件；也可把图片拖到该入口。
2. 上传期间显示占位卡和“上传中”；现有定稿继续有效。
3. 文件完整校验通过后，新卡片出现在本页，标注“上传图1 · 已选定稿”，自动保存选图结果。成功提示：“已将上传图设为第 1 页定稿”。
4. 点击旧候选的单选框可切回旧图；不会覆盖或重写图片文件。
5. 点击上传图可放大查看，卡片提供“修改图片”，并标明“外部上传”。没有“复制该图生成提示词”按钮，因为工具不知道这张外部图的真实生成指令。
6. 上传成品图不改变本页提示词、参考图设置、参与导出开关或其他页选择。已有原图/改图继续到达时，也不抢占上传图的定稿选择。
7. 未开始生图、生成失败、正在生成的页面都能上传成品图；正在执行的生成任务按既有规则继续。

格式建议：PNG / JPG / WebP，单张不超过 20 MiB。参考图无需与页面同宽高比；成品图必须符合该页比例，沿用既有像素舍入容差。校验依据完整解码和实际宽高，不仅检查扩展名。

比例不符示例：“这张图片为 1024×1024，当前页面为 16:9。请换一张 16:9 图片。”本版不提供自动裁剪，以免切掉课件文字。上传失败保留旧定稿，并提供重新选择或重试。

### 7.3 批量导入提示词：一起带入共用参考图

弹窗顺序：

```text
批量导入提示词
[提示词全文输入框]

本次导入的共用参考图（可选）
[沿用当前共用图] [上传新参考图] [不使用]
[缩略图] 文件名                         [更换] [取消使用]

导入预览：23 页 · 23 页跟随共用参考图
[页面编号、页面标题、参考方式的预览列表]
                                      [取消] [导入 23 页]
```

- 保留现有结构化文本与逐行格式的解析、错误提示和页面数量规则。
- 当前课件已有共用图时默认沿用，并直接展示缩略图；没有时默认不设置图片。这里的“不使用”指新课件不设置共用图，新页面仍采用跟随模式，之后可统一添加。
- 选择新参考图只修改本次导入草稿；点击取消时，当前课件共用图和页面不变。
- 点击导入后，先完成当前课件保存，再创建导入课件并同时保存提示词、页序、共用图与页面引用。保存或上传失败时留在弹窗，不生成半份课件。
- 页数、页面与参考图状态在一次导入中一致落盘；不把文件名或参考图说明拼入用户提示词。
- 个别页面的专用参考图在导入后的本页编辑区设置。本版不做按文件名自动匹配多页图片。

### 7.4 批量生成：共用参考图面板

点击顶部“共用参考图”按钮，打开轻量设置弹窗。按钮显示“未设置”或“已设置”，工具栏下方常驻一行摘要，显示当前缩略图、文件名及各参考模式的页数。

```text
共用参考图
[缩略图] style.png           [上传 / 更换] [取消使用]
18 页跟随共用图 · 3 页使用专用图 · 2 页不使用参考图
□ 将未使用参考图的 2 页也改为跟随共用图
                                   [取消] [保存参考设置]
```

- 选择图片后先预览，点击保存再生效；点击取消恢复原状态。
- 更换共用图只更新跟随页面；专用图和显式不使用的页面保留选择。
- 勾选扩展范围选项后，仅把当前未用参考图的页面设为跟随；页面专用图仍保留。
- 清空共用图后，跟随页面显示“共用图未设置，本次使用文字生成”；专用页面不受影响。
- 不增加每次批量生成都必须经过的确认弹窗。正常点击“批量生成”直接沿用当前已保存参数提交。
- 提交前检查各页有效参考图和当前模型能力；指出出错页面，上传未完成或参考文件缺失时不静默退回文生图。
- 引用图片在任务创建时确定。之后更换共用图影响新创建的任务，已经创建但尚未派发的任务也保留原参考图；提供方仍按现有规则在派发时选择。

### 7.5 编辑提示词与重新生成

```text
本页提示词
[完整提示词编辑框]

本页参考图
○ 跟随共用图     ● 本页专用图     ○ 不使用
[缩略图] character.png                  [更换] [取消使用]
本次生成：提示词 + character.png
                                       [收起] [生成这页]
```

- 页面参数里的参考图设置与这里共用同一份状态，避免两个入口互相覆盖。
- 选择跟随时显示当前共用图；此处更换共用图会转到顶部共用设置，以明确影响多页。
- 选择专用时显示上传入口，仅影响当前页。没有成功上传专用图前，不能按专用模式提交。
- “取消使用”会将本页切到“不使用”，不自动改成跟随共用图；重新跟随需要用户主动选择。
- 修改提示词不会清空当前参考图；成功生成的图片仍是新候选。只有该页没有定稿时才沿用已有的首张成功图自动选择规则，不能抢占已有定稿。
- 显示当前实际用于生成的文件名，不只显示“已上传参考图”。

### 7.6 修改图片：原图与补充参考图共同生成

```text
修改图片 · 基于原图1
[原图缩略图]   ＋   [上传补充参考图]
图1：正在修改的原图   图2：补充参考图（可选）

修改要求
[保留图1的文字和布局，把角色改成图2中的机器人。]

将使用：原图1 + robot.png
                            [参数] [收起] [生成修改图]
```

- 所点击的候选图固定为第一张输入；新上传图作为第二张输入。也允许以之前上传的成品图作为第一张图。
- 补充图支持预览、更换、取消使用，取消后恢复只基于原图修改。原图不能在该面板取消。
- 共用参考图和本页生图参考图不会自动加入改图请求；该面板显示的两张图就是这次实际发送的图片。
- 原始提示词、修改要求分别保存。保留用户输入的修改要求，不隐藏地改写或增加“保留风格”等通用指令。
- 若展开“新增一条”建立多个修改任务，每条有独立的修改要求和补充图，默认不自动复制另一条的补充图。
- 点击生成后冻结原图、补充图、文字与参数的组合；后续修改草稿不改变已经提交的任务或失败重试的输入。
- 成功结果标为“改图 N”，显示“基于原图1 · 补充参考 1 张”。保存记录中能重新查看两张输入图与原始修改要求。

### 7.7 窄屏与键盘使用

- 桌面延续多候选横排；宽度不足时候选区在行内横向滚动，页面本身不产生横向溢出。
- 手机将页面信息、候选区、操作区顺序排列，上传入口保持可见；工具栏换行。
- 两张改图输入在窄屏上下排列；弹窗宽度不超过视口，内容可滚动，底部操作可到达。
- 上传控件能用键盘触发；缩略图按钮包含用途和文件名。弹窗沿用现有焦点锁定、Escape 关闭和关闭后焦点返回。
- 上传中、保存成功、错误使用可读状态文字，颜色只作辅助。

## 8. 生效规则、状态与异常

### 8.1 参考图组合

| 操作 | 页面选择 | 最终输入 |
| --- | --- | --- |
| 普通生成或提示词重生成 | 跟随共用图，且共用图存在 | 提示词 + 共用图 |
| 普通生成或提示词重生成 | 跟随共用图，共用图未设置 | 仅提示词 |
| 普通生成或提示词重生成 | 本页专用图 | 提示词 + 本页专用图 |
| 普通生成或提示词重生成 | 不使用 | 仅提示词，即使共用图存在 |
| 修改图片，无补充图 | 与页面参考模式无关 | 修改要求 + 所点击的原图 |
| 修改图片，有补充图 | 与页面参考模式无关 | 修改要求 + 所点击的原图 + 补充图 |
| 上传成品图 | 与页面参考模式无关 | 本地存储并设为定稿，不提交生成 |

### 8.2 上传与保存状态

上传状态：未选择 → 本地预览/校验 → 上传中 → 已保存；任一失败显示原因并允许重试。上传成功前继续保留旧图的关联，依赖替换动作的提交按钮暂停。重试相同成品上传使用同一上传 ID，避免网络响应丢失后出现重复候选。

保存冲突、页面被移除或切换课件时，不能把晚到的响应写进当前页面。服务端以 courseware ID、page ID、expectedRevision 处理，前端再核对请求所属课件。冲突显示“课件已发生变化，请重新打开该页后上传”，保留本次选中的文件供重试。

已有文件找不到时显示“参考图不可用，请重新上传或选择不使用”，阻止对应生成；不要忽略缺失图片后发起收费请求。

### 8.3 长期保存

- 成品图及其页关联、定稿选择保存在后端；浏览器缓存只保留编辑状态，不能成为文件唯一副本。
- 共用图、专用图及页面模式随课件恢复。新导入课件使用自身的共用图 ID，不能串用上一次课件的图片。
- 已提交的修改任务保存主要/补充图 ID，即使当前共用图、页面草稿、定稿选择已改变，恢复及重试也按原输入执行。
- 输入图本地副本保留，不因取消使用、切换定稿或移除页面而自动删除。
- 本轮继续沿用尚未提交的改图编辑框原有生命周期，不额外加入改图草稿库。

## 9. 后端接口与数据落点

以下为实施时的拟定契约，尚未创建接口或迁移数据库。

| 接口 / 模块 | 责任 |
| --- | --- |
| 现有 `POST /api/reference-images` | 校验并保存本地参考图，返回可预览的图片 ID、文件名、格式及宽高；统一设置上传大小限制。 |
| 新增 `GET /api/reference-images/:id` 与 `/:id/content` | 返回参考图元数据及本地图片内容，用于恢复缩略图，不返回中转站 Key。 |
| 新增 `POST /api/coursewares/:id/pages/:pageId/images` | 接收文件、uploadId 和 expectedRevision；成功后关联该页并设为定稿，返回最新课件与新候选。 |
| 现有课件读取与保存 | 返回两类候选来源，校验成品图确实属于该课件该页，复用 revision 控制。 |
| 现有 `POST /api/images/:imageId/children` | 每条任务增加可空的 auxiliaryReferenceImageId，主图来自路径所指的候选。 |
| 候选图片查询 / 下载 | 同时解析生成图和上传图，返回 source、pageId 以及可空的 taskId/batchId。 |
| 任务创建、重试、恢复 | 读取持久化的主要/补充参考 ID，保持顺序并交给适配器。 |
| 定稿 PPT / 无文字服务 | 读取选中的真实图片；上传源图无生成任务时用页面参数完成验证和任务创建。 |

新表只关联现有参考图文件，避免把上传图片包装成一次成功的远程生图。任务补充字段默认 NULL，旧任务继续只发送一张参考图。生成结果和上传图的所有权校验集中到现有课件服务，下载与生成入口复用该查询。

从上传图发起修改时，新建一个真实的生成批次，结果任务仍关联原课件同一页，purpose 为 variation，sourceImageId 指向上传图；不能读取一个不存在的原图 batchId。已有生成图的修改继续沿用目前批次逻辑。

20 MiB 是本轮产品建议值；实施需为受影响上传路由显式设置 multipart 大小限制，并与前端一致，不能依赖服务框架默认上限。适配器的参考图片数和传输格式需按现有版本官方文档核对，不改不相关的请求参数。
