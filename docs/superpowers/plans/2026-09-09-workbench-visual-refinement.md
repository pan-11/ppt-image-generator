# 工作台界面优化执行方案

日期：2026-09-09。状态：**鹿鸣已确认实施；2026-09-10 完成代码与模拟验收**。

本方案基于本地 `main` 的 `d7bfaea`，覆盖课件生产主流程。配套的 `2026-09-09-workbench-visual-preview.html` 是独立布局示意，使用示例内容，不连接业务接口。示意页面可体验展开、选图、预览和监控抽屉；产品行为以本方案为准。

## 1. 建议结论

建议采用**浅色、紧凑、图片优先的生产工作台**：压缩顶部，把一页 PPT 的提示词、图片、定稿和改图入口归在同一条页面记录里。

当前影响观感的主要因素是：多个大面板争夺注意力，同一页内容重复呈现，文字和按钮缺少主次。颜色本身已经有可用基础，继续使用白色、浅灰和现有蓝色主色。

| 方向 | 改动与收益 | 取舍 |
| --- | --- | --- |
| A. 紧凑生产工作台，推荐 | 调整顶部顺序，页面摘要默认展开、详细表单按需展开，合并候选图，统一视觉 | 需要调整组件组合与局部交互；最贴合批量做课件的操作 |
| B. 保留布局，只改外观 | 统一字体、边框、控件和颜色，压缩一些间距 | 改动较小，但同页重复图片、长表单和过多滚动仍然存在 |
| C. 类幻灯片编辑器 | 左侧页面导航，中间大图，右侧属性区 | 更适合逐页精修；会改变批量操作方式，实施范围最大，暂不采用 |

鹿鸣已确认按 A 方向实施。可先完成视觉基础和顶部压缩，再完成页面记录整合，最后统一弹窗与窄屏布局。

### 3.1 页头和课件区

- 页头改为紧凑导航，目标桌面约 56px 高，标题约 20px。使用 `min-height`，长文案与放大时允许增高。
- 当前课件名称成为页面的主要标题；有明确的“课件名称”标签，长名称可以编辑、查看全文。
- 名称下面显示保存状态与页数、定稿数。成功状态只在现有保存状态确实成功时显示；保存中和失败保持可见。
- “打开课件”“保存当前课件”“提示词库”“无文字版本”“导出定稿 PPT”保持各自入口与已有行为，按管理/生产输出分组。
- 没有课件时显示“当前编辑内容”与现有保存说明，不假装已经保存，也不为展示标题自动创建课件。
- 顶部独立的历史刷新说明面板移到历史区；刷新仍然是手动刷新。
- 页头不吸顶；任务操作条吸顶。避免多层吸顶区遮住内容。

### 3.2 默认参数改为摘要

- 默认显示一条摘要：模型、比例、分辨率、每页张数、参考图状态、当前渠道。
- 明确文案“新页默认参数”。普通模型、渠道信息用中性文字；异常才使用警告/错误色。
- “修改参数”展开已有表单；参数校验失败时必须能看到错误和修改入口，可以自动展开对应参数区。
- 默认参数继续只影响新建/导入页面。原有全局参考图行为保持不变，不引入“自动同步已有所有页”。
- 在窄屏中允许摘要分成两行；模型全文和文件名在展开区可见，不用无限缩小字号硬塞一行。

### 3.3 一个吸顶任务操作条

- 包含页面数量、导入、新增、历史锚点、监控入口和批量生成。
- 保留 `SubmitBar` 原有提交锁、模型校验和错误信息，将它整合到任务头部；移除上下重复的深色大提交面板。
- 唯一主按钮为“批量生成（N 页）”，统计口径与现有 `readyTaskCount` 一致：有提示词、且实际参与这次提交的任务页。不改成“仅生成未完成页”，也不因页面折叠或导出勾选改变提交范围。
- 如果每页多张，旁边另显示预计图片总数。页数与图片数分开，避免将一页多候选理解成多页 PPT。
- “新增页面”和单页生成用次级按钮；已有页级生成入口保留，不能强制用户每次重跑整批。
- 监控入口移入操作条，桌面释放现有 88px 预留侧边空间。抽屉依旧由右向左展开，桌面 420px、窄屏全宽、默认关闭。
- `useActiveBatch`、当前批次和轮询仍由 `App` 持有。吸顶、折叠、开关抽屉都不暂停队列或发起生成。
- 桌面吸顶 `top: 12px`；窄屏允许操作条换行、主按钮独占下一行。320px 或 200% 缩放导致吸顶区过高时改为普通流布局。
- 历史锚点和任务锚点要留出吸顶避让距离。导航只滚动，不切换路由、不卸载编辑器。

## 4. 一页 PPT 对应一条页面记录

### 4.1 默认折叠状态

- 左侧：页序、页名/备注、生成状态、参数摘要。页名沿用已有数据，缺少时展示“第 N 页”；不改写原始标题或导入文本。
- 中间：唯一的候选图片区。使用 160×90 的图片框、`object-fit: contain`，不裁切设计；同页多个版本水平排列。
- 右侧：编辑提示词、页面设置、单页生成、“更多”和参与导出勾选。
- 常见桌面行高目标约 150–180px，内容增长时自然增高，不通过硬裁切达到指标。
- 无图片时也有清楚的占位与状态。排队、生成、失败、待生成各用文字说明；错误页提供已有重试/生成入口和完整错误展开。
- 空白草稿保留原有数量与内容；第一次使用时展开首个空白页的提示词，避免只有摘要却不知道从哪里开始输入。

### 4.2 提示词与页面设置

- “编辑提示词”在本行展开完整文本框，可手动调整高度。展开时保留全部换行，不截断原文。
- “页面设置”展开该页模型、比例、分辨率、张数、参考图选项和上传入口。未展开时有真实参数摘要。
- “复制本页提示词”指当前页的编辑文本；“复制图片提示词”指该候选实际使用的提示词，二者不能合并或用错来源。
- 折叠采用保留组件实例的方式，例如受控隐藏区域。已经输入的改图提示词、上传状态、参数和错误不能因为收起而丢失。
- 展开状态按课件 ID/页面 ID 标识，不能按数组下标或当前显示页序标识。移动页面、轮询更新不应让展开状态串到另一页。
- 表单有错误时提供明确入口并定位字段。不要把错误藏在折叠区里仅保留一个禁用按钮。

### 4.3 合并候选图和定稿选择

- 将 `TaskRow` 的图片浏览和 `PageSelectionPanel` 的定稿候选合并成一套可见候选条。每个候选保留稳定 image ID。
- 候选属于同一个页面：原图、同批多张输出和所有子图，只有一个 `selectedImageId`。
- 预览与设为定稿是两个明确动作。点击图片打开大图；单选框/“设为定稿”才改变最终选择，避免看大图时顺便换定稿。
- 被选中的候选有单选状态、边框和“已选定稿”文字。选择另一张后，原候选取消选中。
- 显示“原图”“改图”及必要的来源提示。子图仍能找到父图，不能把递归来源关系仅变成无关联的图片数组。
- 校验失败、定稿缺失等状态沿用现有规则。不能因为统一缩略图而让无效图片被当作可导出结果。
- 历史尚未保存为课件时，保留现有历史恢复/保存路径，不凭空伪造 page/task 链接。
- 定稿选择和候选显示分开处理：轮询到新候选不覆盖已经选好的定稿。

### 4.4 改图面板

- 每张候选提供“基于此图修改”，点击后展开该候选的修改区。
- 明确展示输入参考图、修改提示词和“生成改图”。已有多条子提示词、参数设置和子图继续修改功能保留。
- 已有 `onCreateChildTasks(parentImageId, tasks)`、独立输出任务和 provider 选择逻辑保持原样。
- 切换正在看的候选不会清空其他候选的未提交草稿。原图和子图的草稿身份仍绑定 image ID。
- 不使用新的跨页侧栏编辑器，减少焦点跳转和状态搬迁。

### 4.5 页级次要操作

- “复制”明确改为“复制页面”，避免被误认为复制提示词。
- 上移、下移、复制页面、从课件移除收进“更多”；当前页序旁保留可发现的入口。
- 从当前课件移除前确认，文案明确只移除当前页面，历史图片仍保留。确认后沿用原有移除回调，不增加真实图片删除。
- 参与 PPT 导出的勾选保持在行内。取消勾选不隐藏页面、不删除提示词，也不改变提示词导出的内容范围。

## 5. 历史、提示词库与无文字版本

### 5.1 历史记录

- 保持“一个批次一条记录，同批图片一行”的布局与 160×90 固定缩略图。
- 历史标题简化为“生成历史”。刷新按钮放在这里，与手动同步的说明相邻。
- 下载目录收进可展开的“图片导出设置”，明确这是批量图片导出的目录，不把它混同为 PPT 的浏览器下载位置。
